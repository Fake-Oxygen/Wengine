# API reference

Per-module contract documentation for everyone embedding WEngine into
another application: graphical front ends, link-bus readers, custom
sinks, and new solvers. The engine's public surface is the header tree
under `include/wengine/<module>/`; Doxygen extracts that tree to
`build/docs/doxygen-xml/` and Breathe renders the XML inside the module
pages below.

Each page pairs a responsibility narrative — what the module owns, which
modules it sits between, which dependency rules it obeys — with
compile-grade usage patterns and rendered API listings. For the full
module dependency map, see the [Architecture](../dev/architecture.md)
page.

## Modules

| Module | Responsibility | Page |
|--------|----------------|------|
| `units` | Typed physical quantities (`units::Value<Dim>`), SI dimensions, literals, and the single suffix-scale table | [units](units.md) |

| `world` | Live simulation state: clock, entity registry, SoA component pools, deep-copy snapshots, binary save/load | [world](world.md) |
| `physics` | Shared physical-model seam: component declarations; the models live in `solvers/` and `world/` | [physics](physics.md) |
| `solvers` | Closed-form calculators, the stepped-solver registry, headless and paced run drivers, and IC datasheet solvers | [solvers](solvers.md) |
| `signal` | Stamped signal sources: kinds, params, the `kQuantities` table, stable serials | [signal](signal.md) |
| `emit` | Output sinks and edge-side routing wrappers | [emit](emit.md) |
| `link` | Shared-memory and socket transport: frames, endpoints, wire formats | [link](link.md) |
| `logic` | Netlist logic domain: parsing, state, layout, topology | [logic](logic.md) |
| `ros2` | Robotics bridge (ROS 2 integration) | [ros2](ros2.md) |

## Page shape

Every module page follows the same structure:

1. Intro prose: the module's responsibility, its collaborators, and the
   dependency rules it obeys.
2. **Usage pattern**: one minimal, complete C++ program. It compiles and
   runs exactly as documented.
3. **Key entities**: Breathe directives for the curated surface an
   embedder needs first.
4. **Complete module listing**: a namespace-level directive that renders
   every public entity of the module, so nothing undocumented can hide.

The listings draw their content from the Doxygen extraction of
`include/wengine/**` (regenerated by `docs/build.sh`). Directive
content reflects exactly what the headers declare; the prose and usage
patterns carry the calling contracts.

## Directive example

Every rendered entity is a MyST directive naming the entity fully
qualified, with the Doxygen project selected:

````markdown
```{doxygenclass} wengine::units::Value
:project: wengine
```
````

Rendered, that directive produces the class documentation:

```{doxygenclass} wengine::units::Value
:project: wengine
```

The same pattern carries over to the other entity kinds: classes and
structs use `{doxygenclass}`/`{doxygenstruct}`, free functions
`{doxygenfunction}`, enums `{doxygenenum}`, variables and constants
`{doxygenvariable}`, and whole namespaces `{doxygennamespace}` — each
with `:project: wengine`. Files without a namespace (see
[physics](physics.md)) render through `{doxygenfile}` with the header
basename.

```{toctree}
:maxdepth: 1

units
core
world
physics
solvers
signal
emit
link
logic
ros2
tui
cli
```
